# 28. Git Workflow

## Branch Strategy

- Use short-lived branches for each change.
- Prefer descriptive branch names such as `feat/foundation-api`.
- Merge through pull requests only.

## Commit Standard

- Use Conventional Commits.
- Examples: `feat: add api health endpoints` and `chore: scaffold workspace foundation`.

## Review Requirements

- Every PR requires at least one review.
- Build, lint, and tests must pass before merge.
